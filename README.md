# 冷链温控与批次放行台

冷库与冷藏车的温控值班台：录冷库与探头、登批次、盯温度记录、算超限与断链、判放行还是拒收。

## 运行

```
npm install
npm start
```

默认端口 5247（`PORT` 可以覆盖），数据存在 `data/db.json`，页面在 `/`。

## 页面

- **概览**：冷库与运行中数量、探头数量与已过校准期的探头数、批次总数与各状态条数、温度记录条数与人工记录数、放行与拒收条数、当前满足放行条件的批次数与被挡下的批次数、没有任何温度记录的批次数、最高与平均 MKT、按冷库一行给出探头与批次数。
- **冷库与探头**：冷库台账（编码、名称、类型、位置、库位、状态）与探头台账（编号、所属冷库、位置、状态、校准有效期、记录条数），都带增改删。
- **批次**：批次清单（批次号、品名、规格、件数、所在冷库、入库时刻、状态、温度记录条数、最长超限、累计超限、MKT、断链数、放行情况），可一次勾选多批走**批量预检放行**，行内展开逐条温度记录、超限段、断链缺口、放行判定五项与放行单，并提供单批「放行」「拒收」入口。
- **温度记录**：记录清单（批次、探头、时刻、温度、来源、登记人、是否超限），支持按批次与探头筛选、单条新增与删除。
- **放行台账**：上半部是**批量放行单**（单号、时刻、经办人、批次数、件数合计、成功/失败数、预检时刻、依据，可展开批次清单），下半部是逐批放行与拒收记录（批次、决定、时刻、经办人、当时的 MKT、最长超限、累计超限、断链数、所属批量单号、依据）。

## 口径（页面上的说明与数字都要与本段一致）

1. **温度带**：默认 2 到 8 摄氏度（可在设置里改），低于下限或高于上限都算超限。
2. **超限段**：按时刻顺序逐条判，连续超限的时段算一段，**中间只要有记录回到范围内就断开**；每段的时长按该段相邻记录的实际时刻差累加。
3. **累计超限**：一个批次从入库到当前，所有超限段的时长之和；**跨月不重置**，按批次周期累计。
4. **断链**：相邻两条记录的时刻差超过 `chainGapMinutes`（默认 15 分钟）算一处断链，缺口时长按实际时刻差算。
5. **MKT（平均动力学温度）**：按动力学公式算，写成 `MKT = −Ea / (R × ln((Σ e^(−Ea/(R·T)) ) / n)) − 273.15`（活化能 Ea 取 83144 J/mol、气体常数 R 取 8.314，T 用开尔文，n 为参与计算的记录条数）；**不是把温度取平均**。
6. **放行判定**：页面与预检逐条列出五项——① 至少有 1 条温度记录；② 单次连续超限不超过 `allowExcursionMinutes`（默认 30 分钟）；③ 累计超限不超过 `allowTotalExcursionMinutes`（默认 120 分钟，跨月不重置）；④ 全程没有断链；⑤ 参与判定的探头都在校准有效期内。五项同时满足才算满足放行条件；**没有任何温度记录的批次不能放行**。每条不通过都给出实际值、阈值与"差多少"。
7. **同一探头同一时刻既有自动记录又有手工更正记录时，以手工记录为准**；停用探头名下的记录不参与判定。
8. **停用与检修中的冷库**：其批次仍然照常记录与判定，但在清单里要标出来。

## 批量放行的规矩

一次选中多批，先预检、确认后再放行，流程与约束如下：

1. **先预检再放行**：`POST /api/batch-release/precheck` 对选中的每一批跑一遍放行判定，逐批返回结论（通过/被挡下）、被**哪一条判据**挡下、**实际值与阈值、差多少**，并给每批一个本次预检的指纹。预检不改任何数据。
2. **不通过的批不许混进去**：只要有一批预检不通过，预检结果就是 `allPassed=false`；前端不允许直接放行。放行接口也会在写入前用最新数据再复核一遍，挡下的批无论如何都混不过去。
3. **失败整体回退**：`POST /api/batch-release/execute` 分两阶段——第一阶段对每一批复核（状态、最新判定、预检指纹），任何一批不过就整单拦下，**一条数据都不写**；第二阶段先对 `batches / releases / batchReleases` 做快照，再逐批落放行单、改批次状态，落完整体核验，中途异常或核验失败都回滚到快照。返回里点名是**哪一批、什么错误码、什么原因**导致整单失败，并带 `releasedCount:0、rolledBack:true`，不会出现"前几批放了、后几批没放"却看不出来。
4. **预检过期会被拦下**：预检指纹覆盖判定门槛设置、批次本体与状态、参与判定的有效温度记录（去停用探头、手工记录优先之后的结果）、相关探头的状态与校准有效期。预检之后、放行之前只要这些被别人改动（补录记录、删除记录、判定重算、改设置、探头停用或校准期变化、批次已被决定），放行时该批返回 `BATCH_STALE`（或 `BATCH_PRECHECK_FAILED / BATCH_ALREADY_DECIDED`）整单拦下，提示**重新预检**，不拿过期结果放行。
5. **单据与汇总**：成功后生成一张**批量放行单**（`batchReleases`，单号 `br-xxxx`：时刻、经办人、依据、批次数、件数合计、成功数、预检时刻、批次清单），同时给每一批生成独立的逐批放行单（`releases`，单号 `rl-xxxx`，带 `batchReleaseId` 回指批量单、经办人及当时的 MKT/超限/断链）。批量单与逐批单据都在"放行台账"里可查。一次最多 100 批，清单不能为空、不能重复。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | /api/health、/api/summary、/api/settings | 健康检查、概览、设置（PATCH 可改） |
| GET / POST | /api/rooms | 冷库清单（支持 status、type、keyword）/ 新增 |
| GET / PATCH / DELETE | /api/rooms/:id | 详情（含探头与批次）/ 修改 / 删除 |
| GET / POST | /api/probes | 探头清单（支持 roomId、status）/ 新增 |
| PATCH / DELETE | /api/probes/:id | 修改 / 删除 |
| GET / POST | /api/batches | 批次清单（支持 roomId、status、product）/ 新增 |
| GET / PATCH / DELETE | /api/batches/:id | 详情（含记录、超限段、断链、放行单）/ 修改 / 删除 |
| GET | /api/batches/:id/release-check | 这个批次的放行判定 |
| POST | /api/batches/:id/decision | 放行或者拒收，body `{decision, decider, decidedAt, basis, remark}` |
| POST | /api/batch-release/precheck | 批量预检，body `{batchIds:[]}`，逐批返回结论、挡下判据与差值、指纹 |
| POST | /api/batch-release/execute | 确认后批量放行，body `{batchIds, decider, basis, remark, checkedAt, fingerprints:{批次id:指纹}}`；两阶段复核+快照回退 |
| GET | /api/batch-releases、/api/batch-releases/:id | 批量放行单清单（支持 batchId、decider）/ 单据详情（含批次清单） |
| GET / POST | /api/records | 温度记录（支持 batchId、probeId、source、from、to）/ 新增 |
| DELETE | /api/records/:id | 删除一条记录 |
| GET | /api/releases | 放行台账（支持 batchId、decision） |

出错的返回统一是 `{"error":{"code":"...","message":"...","details":{...}}}`，`details` 里会点名是哪个字段没过。
